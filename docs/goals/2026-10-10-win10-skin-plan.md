# План: внешний вид диспетчера задач Windows 10 для Task Manager (clean room, egui)

> Это исходный план внешнего вида. Последующее утверждённое удаление legacy GTK/Meson и
> эксперимента Silver не меняет clean-room контракт. Graph core теперь local
> `crates/mc-graph-core`; единственный required submodule — magpie; provenance —
> `docs/PROVENANCE.md`. Исторические сравнения — `perf/history/bench-latest.md`,
> `perf/history/bench-win10.md`, `perf/history/bench-win10-full.md`; текущий `bench-idle`
> измеряет только egui wgpu/glow (метод и валидность — `perf/README.md`).
> Зачистка сама не доказывает завершение W5 или функциональный паритет.

## Context

GTK-интерфейс уже заменён на egui (порт: `docs/goals/2026-10-10-egui-gui-port.md`). Сейчас egui-интерфейс повторяет Adwaita/GNOME. Пользователь хочет полностью заменить его на вид диспетчера задач Windows 10 с точностью до пикселя.

Метод — clean room: Microsoft-кода, ресурсов, иконок и шрифтов не берём. Делаем по измерениям четырёх скриншотов в `references/` (1030×705, 96 DPI, светлая тема).

**Решения пользователя:**
- вкладки только 4, как в референсах: Processes, Performance, Details, Services;
- свой заголовок окна в стиле Win10 (client-side decorations);
- шрифт Selawik в комплекте (OFL, метрически совместим с Segoe UI); если в системе есть Segoe UI, берём его;
- Adwaita-интерфейс удаляется полностью, тёмной темы не будет.

**Мои умолчания:**
- первоначально имя приложения и иконка оставались Mission Center; это решение отменено полным переименованием в Task Manager и пользовательской иконкой (см. Material Decisions в `2026-10-10-win10-skin.md`); никаких марок Microsoft;
- рендерер по умолчанию glow: в бенчмарке R4 103 МиБ видеопамяти против 423 у wgpu при равном CPU;
- `references/` в git не кладём.

**Что значит «пиксель в пиксель».** В референсах текст сглажен ClearType с цветной субпиксельной окантовкой, а egui сглаживает текст в градациях серого. Поэтому критерий такой:
- геометрия и цвета не-текстовых элементов совпадают точно (линии, фоны, рамки, сетки, ячейки, размеры);
- текст совпадает по положению и размерам с допуском ±1 px; побайтового совпадения глифов не будет.

## Clean-room порядок
1. **Спецификация из измерений.** `tools/measure_refs.py` (PIL, только чтение, путь к референсам через `MC_REFS`) извлекает факты: координаты, размеры, цвета, шаги сеток. На этой основе пишется `docs/win10-spec/spec.md`. Там же лежат «пробы»: списки точек `(вкладка, x, y, ожидаемый цвет)` для автоматической проверки.
2. **Реализация только по spec.md.** В код и тесты не копируется ни один пиксель референсов. Иконки рисуем сами векторно через egui `Painter` по функциональному описанию (шестерёнка, шеврон, кружок со стрелкой, ячейка процесса) — без обводки чужих.
3. **Референсы** остаются локально (`.gitignore`) и нужны только для ручного сравнения бок о бок.
4. **Юридическая оговорка.** Clean room снимает вопрос авторского права на код и ресурсы. Внешнее сходство (trade dress) остаётся риском; это не юридическая консультация. Поэтому имя, иконка и тексты остаются своими.

## Архитектура
Логика и данные остаются как есть: `mc-magpie`, `mc-core` (`Tree`, форматтеры, `Config`, i18n), `mc-graph`, оболочка `App::logic` (приём данных, команды, `ConfigWriter`, waker на 1 мс). Слой отображения в `crates/mc-ui` переписывается.

**Тема и основа:**
- `win10/metrics.rs`, `win10/palette.rs` — все числа и цвета из spec.md, в одном месте.
- `win10/fonts.rs` — Selawik (Regular, Semilight, Light, Semibold) из `crates/mc-ui/assets/fonts/` + `OFL.txt`. Если fontconfig находит Segoe UI, используется он. Заменяет `fonts.rs` и `theme.rs`.

**Виджеты (`win10/`):**
- `titlebar.rs` — CSD через `ViewportBuilder::with_decorations(false)`. Перетаскивание — `ViewportCommand::StartDrag`, двойной клик — развернуть. Кнопки свернуть/развернуть/закрыть рисуются `Painter`, края изменения размера — `ViewportCommand::BeginResize`.
- `menubar.rs` — File/Options/View с выпадающими списками в стиле Win32.
- `tabs.rs` — полоса вкладок.
- `listview.rs` — таблица в стиле Win32 ListView. Перерабатывается из `table.rs`: заголовок с градиентными разделителями и сводной строкой, каретка сортировки, строки 28/19 px, тепловые ячейки, выделение, своя прокрутка 15 px, изменение ширины колонок перетаскиванием.
- `footer.rs` — «Fewer details» (своя иконка) + кнопка или ссылка.
- `stat.rs` — блоки подпись/значение и таблица ключ/значение.

**Графики.** В `mc-graph::Graph` добавляется `GraphStyle::Win10`:
- прямые углы, рамка 1 px;
- сетка с фиксированным шагом (10 делений по вертикали, 64 px по горизонтали) и прокруткой вместе с данными;
- заливка цветом устройства с малой непрозрачностью, линия 1 px;
- маска скруглённых углов отключается.

Существующая логика кеша и `mc-graph-core` переиспользуются.

**Страницы (`win10/pages/`):**
- `processes.rs`:
  - группы как в Win10 по View → Group by type: «Apps» и «Background processes» через `Tree::apps`; без группировки — плоский список;
  - тепловые колонки CPU/Memory/Disk/Network, GPU — через контекстное меню заголовка;
  - кнопка End task (terminate);
  - компактный режим «Fewer details» с маленьким окном, списком приложений и End task.
- `performance.rs`:
  - список устройств и страницы CPU/Memory/Disk/Ethernet и Wi-Fi/GPU/Fan/Battery в одном стиле: крупный заголовок, модель справа, подпись «% Utilization over 60 seconds», график(и), блоки статистики, таблица ключ/значение;
  - у CPU как в референсе: сетка по логическим процессорам и общий режим (Change graph to);
  - модели страниц (`perf/*.rs`: данные, форматирование, `data_summary`) переиспользуются, переписываются только их `ui`/`details_ui`.
- `details.rs` — плоский список процессов: Name, PID, Status (из `ProcessState`), User name, CPU, Memory. Колонку UAC (понятие Windows) не делаем.
- `services.rs` — Name, PID, Description, Status, Group (unix-группа из magpie).

**Данные для Details.** «User name» требует uid процесса, а в `magpie_types::Process` его нет:
- uid читается из `/proc/<pid>/status` в фоновом потоке gatherer `mc-magpie`, а не в UI;
- имя берётся из разбора `/etc/passwd` с кешем;
- результат — новая карта `Readings::process_users`; magpie-types не меняем;
- во Flatpak (без доступа к `/proc` хоста) значение «N/A».

**Меню — только пункты с реальным поведением:**
- File: Run new task (поле ввода команды, отсоединённый запуск в фоновом потоке), Exit.
- Options: Always on top (`WindowLevel::AlwaysOnTop`), Set default tab, Settings… (наши настройки в диалоге-вкладках Win32: интервал, единицы, графики).
- View: Refresh now (новый `Request::RefreshNow` будит gatherer), Update speed — High 0.5 с / Normal 1 с / Low 4 с / Paused (`app_update_interval` + пауза приёма), Group by type, Expand all, Collapse all.

**Диалоги** (свойства процесса и сервиса, логи, SMART, eject, about, first run) переоформляются в стиле Win32. Логика из `dialogs.rs`/`smart.rs` остаётся.

**Удаляется:**
- `theme.rs` (Adwaita-токены), `apps.rs`, старые `ui` в `perf/`, `placeholder.rs` (заменяется простыми пустыми состояниями);
- переключатель светлой/тёмной темы. Ключ `window-interface-style` в конфиге игнорируется.

**Строки.** Новые английские подписи Win10-интерфейса (например «Fewer details», «End task», «% Utilization over 60 seconds») — новые msgid, переводов к ним сначала не будет. Строки, совпадающие с существующими msgid (Processes, Services, CPU, Memory…), берутся из текущего каталога.

## Проверка
- **Пробы без референсов (CI):** `crates/mc-ui/tests/win10_probes.rs` рендерит каждую вкладку через egui_kittest в 1030×705 при ppp=1 на синтетических данных со структурой как в референсе (строки, колонки, выбранное устройство). Цвета в точках-пробах из spec.md должны совпадать точно; положения текстовых блоков (bounding box по маске ненулевого текста в заданных областях) — с допуском ±1 px.
- **Локальное сравнение:** `tools/compare_refs.py` выдаёт карту различий рендер↔референс по не-текстовым областям (маска из spec) и процент совпадения пикселей. Цель — 100% в не-текстовых областях; ручной просмотр бок о бок.
- **Регрессии:** `cargo test -p mc-core -p mc-magpie -p mc-graph -p mc-ui`, `cargo clippy ... -D warnings`.
- **Производительность:** `cargo xtask bench-idle` — UI CPU в простое не хуже текущих 0.75%, 1.1 кадра на обновление.
- **Ручной smoke на KDE Wayland:** перетаскивание и изменение размера своим заголовком, разворачивание, меню, End task, переключение вкладок, Fewer details.

## Риски
- **Selawik ≠ Segoe UI.** Метрики совместимы, но рисунок глифов отличается; если Segoe UI установлен у пользователя, совпадение точнее.
- **CSD на Wayland.** Тени и скругление окна у KDE отключаются; края изменения размера рисуем сами; поведение «прилипания» к краям экрана зависит от композитора.
- **Высокие уровни тепловой карты и состояния hover/selection** в референсах не видны — это своё проектирование, помечается в spec.
- **DPI.** Измерения сделаны при 100%; при другом масштабе все метрики масштабируются через `pixels_per_point`, линии 1 px выравниваются по физическим пикселям.
